九霄固定在 `f1fe6ea561c5ef4d1ec670b7a406625ce5df774c`。非生产 `loadTurnPlugin` 实际接受 `prologue-v1-candidate-20261005`，强制校验的语义 SHA-256 为 `8b938f92e0427ef03b44a7fe6cb90f8fb208e9ca7140a316dae187dfdd422006`。上游同时报告 bundle 和 plugin-source 两项历史字节摘要不匹配。审批表明确把这两项作为诊断字段，加载器正常执行语义门禁并返回固定插件。未使用生产审批。

在独立的固定规则动作预演中，初始去望气台产生 R1 到达，直接回芦花渡产生 R2 受阻，再要求到当前望气台返回 rejected、修订仍为 2。保留冻结输入和这项不符合直觉的结果。驱动保留这三个请求，检查拒绝不增加修订，再用既有公开的子区域动作推进到 R3；另走公开的调查障碍、绕行和复访路径。这是动作调度依据，尚无该路径的 B2 数据库回执。

## 读证实现与范围

每个新存档只允许受信启动器注册一次，按 owner/save/root 隔离。R0 同时约束正常创建返回和 PG 独立读回的完整状态。串行提交后，捕获当前完整 SaveEnvelope、原始 receipt 摘要、事件累计数与端点、PG 读取截面及时间。捕获不成功就留下历史缺口。重启将丢失进程内捕获；不支持为既有玩家存档补建过去的证据。

历史读取调用原认证服务，设计在同一 `REPEATABLE READ READ ONLY` 事务内查所有者、存档、回执及按序事件行。检验链、已捕获的端点、修订/序号连续性、root、逐事件字段、请求键和成功类型，再从 R0 用上游 replayEvents 与固定 reducer 重放并核对每个完整目标态。随后用独立的新 SQL 语句一次检查同一 token 的有效期、账号和存档状态。该语句的 MVCC 截面是设计的授权交付点；已经返回的事实无法追溯撤回。重复查询重新鉴权，返回首次获证的时间和修订，避免倒写历史。实际数据库的隔离级别、撤权可见性及对账结果均待测。

正例驱动采用真实上游认证与游戏服务方法，含 R1、较晚重登录、同地点子区域、受阻、绕行、复访、并发读写及最终授权前登出的测试代码。普通 HTTP 游戏路由、关闭账号和全部生命周期对照尚未验收。上游 CloudArchiveLifecycle.change 仅接受 schema 1 的本地归档；schema 3 原生规则存档不能经此方法软删除。将来如缺正常受权的生命周期入口，应单列这个依赖。不得向存档表直接写入垃圾箱记录凑出真实正例。
