## Gate B · 根因与提交边界

H2R 在读取片段时直接改 pending、titles、settled 和 duplicates，并可同时产生候选。后半句限定未被解析时，已经登记的结果会留在排名中。另一个问题是后来的登记会继续取用因裁决失效的旧签条。

H3A 在独立入口先用既有受信契约核验已保存历史及来源，再收集本修订的陈述、文书、登记、权利结果和反证。旧解析器用于识别句型，临时解析状态即弃；旧权益候选必须在 H3A 的账本重建。新账本按资产和权益种类分别绑定，在隔离草稿上核查整回合，未解析且可能影响处置的从句会阻止提交。只有整次审查返回才公布本回合状态、去重指纹、有效候选与因果边。晚到裁决在新的 learnedAt 取消相关候选及依赖它的后续候选，当时的旧排名仍可复现。明确解除保全并新签有效文书后可以结算。见[收集器](../../packages/highlights/h3a/collect.mjs)、[事务审核](../../packages/highlights/h3a/transaction.mjs)和[回放契约](../../packages/highlights/h3a/README.md)。

### 复跑与回退

在有现有锁定依赖和 contracts/dist 的仓库根运行：

```powershell
node --permission --allow-fs-read=* packages/highlights/h3a/targeted.mjs
node --permission --allow-fs-read=* packages/highlights/h3a/guards.mjs
python -B packages/highlights/h3a/record.py
```

record.py 重建定向、公开回放、回归与性能回执。旧 H2R 红灯在独立临时目录运行，不覆盖原证据。研究宿主回退时直接调用 [replayHighlights2R](../../packages/highlights/h2r/replay.mjs)。没有生产入口切换、数据库迁移或付费授权变更。
