将现有 `packages/luna-text/run.mjs` 的“操作人手动在终端配置环境变量”流程替换为**由 Codex 启动、能让道主自己访问的一次性安全输入窗口**。新界面应具备：隐藏输入、一次性发送、受信服务端临时持有、独立预检、明确一次性测试确认与脱敏结果回执。严禁生成公开无认证的密钥收集网址或把密钥要求发送到聊天。

这项任务授权**实现安全输入能力与无网络验证**。此前已限定的一次 Luna 文本请求（模型 `gpt-6-luna`、总预算 $0.10、合成酒馆、最多 1 次）不变，禁止扩展成图片测试或其他调用。**输入 Key 不等于马上执行真实请求**；需预检 READY 和操作人在页面明确点击“开始本次唯一文字测试”后，才允许走现有一次性发送门禁。若尚不能安全提供页面，返回 BLOCKED，不以其他方式窃取或接收 Key。

## 输入页面的最小安全设计

- UI 只显示必要控件：`OpenAI API Key`（`type=password`，默认不自动填充），`检查配置`、`开始唯一一次 Luna 文字测试`、`清除`。显示固定模型、预算 `$0.10`、数据范围“开发自编合成酒馆文字”、图片 API 禁用。
- 只服务于操作人的私有开发环境。若是 loopback 页面，用不可预测且短期有效的**一次性会话 nonce**、校验 `Host` 和 `Origin`、拒绝跨站表单/跨站 fetch；默认拒绝同网段远程访问。随机端口由运行端实际打印。使用严格 CSP、`Cache-Control:no-store`，禁用第三方脚本、分析/埋点/错误上报、第三方字体、Service Worker。必要时用户点击之后才启动接收端口，超时后停止监听。
- API Key 只通过 **POST 请求正文**从表单传给受信后台，不能放在 URL、查询参数、fragment、日志、exception、截图、浏览器 localStorage/sessionStorage、Cookie、GitHub、数据库或任何持久文件里。不要将输入页面的密钥字段回显给客户端。尽量禁止浏览器自动填充并清理输入框；说明客户端输入时会短暂存在浏览器内存。
- 后端只在单次会话内内存持有密钥，传入既有 `cardModel`/OpenAI 调用边界后即清理引用。若必须用子进程，优先通过一次性受保护 IPC/stdin 传入，而不是要求用户手动设置环境变量；子进程参数/命令行不得包含 key。不得把 Key 注入可被任意下游构建或 Chrome 继承的长生命周期环境；如果使用临时环境变量，严格限制继承范围和生命周期，并在报告写清风险。
- 对外实际 HTTPS 目的地必须固定为受信 `https://api.openai.com/v1/responses`，沿用上游 TLS/DNS 安全限制，不允许前端提交模型/host 或拦截/代理到第三方域名。敏感 header 不记录。
- 密钥提交后**不能单独为了测试余额/模型权限而发一笔付费推理请求**。预检可核对本地权限/日期门禁及官方明确支持的无计费账户检查；项目权限无法零成本确认时标“待首次真正请求验证”，不虚称已确认。任何服务端明确 401、403、429 或响应未知立即 STOP。
- 若浏览器/后端崩溃、窗口关闭、过期、用户退出或完成测试，清空内存凭据并关闭一次性页面。不能给用户设置永久“保存 Key”开关。
