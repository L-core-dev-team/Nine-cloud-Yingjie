## 3. B｜修复限制范围误拦，保持原输入与原模型输出

### 3.1 已确认的代码问题

原 `pilot.py validate()` 将 `sceneCandidate.excluded + sceneCandidate.limits` 合并，只要焦点引文与其中任一引文的字符范围重叠就返回 `excluded-focus`。

### 3.2 最小改法

在独立目录 `packages/ai-timing-pilot/repair/` 建立小型修复入口。原 `pilot.py`、`fixture.json`、`protocol.json`、schema、rubric 及原验收程序保持原样；复用其来源定位、纯函数与归档读取，不全局放开排除规则。

修复后的证据表示至少能区分：

- 当前正向支持的实体、属性或可见范围及其引文。
- 限制针对的实体、属性或范围；“深处未知”不等于“同句写到的近处也未知”。
- 历史、假设、转述等非当前画面层。
- 当前缺少证据，与明确观察到的限制，不能混成一条无目标的禁止语句。

新篇保留原 unknown 目标，但也要核查原引文本身是否支持该限制。例如“仍守在石壁前”直接支持当前位置，不能单独证明壁后声源的认知状态。没有当前限制依据就保留该目标缺证，或另标来自前缀的历史未知，不把当前位置整句降为 unknown。

原数据缺少必要结构时，允许用**可追溯的来源标注**补充目标与支持范围：每项记录原题包/原文哈希、修订、原引文、补充解释及其来源，明确为执行方对照标注。它不是模型补答，也不能计作原模型提取能力提升。标注只补当前原文可支持的关系，不引用未来、评分或期待动作；无可靠依据继续待审。

验证器使用同一种带目标的规则处理全部二十份归档，不按 old07/new02/new06 的槽位、特定人名或故事名直接返回通过。引文存在与不重叠也不能独立证明自由文字的全部含义；本轮目标是消除已确认的误拦，保留语义评阅边界，不重建通用中文解析器。

不能只把原 excluded-focus 结果的 valid 改为 true：旧校验会在首处冲突提前退出，修复后必须重新完成整份答复的结构、全部引文、条件方案及一致性检查。接受逻辑不得读取 rubric、semantic-review 的分数/通过判定或作者期待动作；这些材料仅用于独立评价。

### 3.3 原实验输入绝不能被“修好后重新伪装”

原二十个模型收到的是真实旧题包。new02 等原结果是无效，后继候选当时看到的也是旧无效标记。修复后不能重新生成带新有效标记的题包，再宣称原模型曾看过新输入。

采用两层记录即可：

1. **原实验层：** 原题包字节、首答字节、首次处理、实际 previousRecommendation、四份审核及绑定原样保存；原链仍按旧逻辑复核。
2. **修复回放层：** 读取原题包与原答，另附来源标注/证据视图和新版校验结果；每行同时绑定原 packet/raw/result 哈希、来源标注或证据视图哈希、修复规则版本及新结果哈希，单独存档和形成回放链。标注变更形成可追溯的新结果，不能继续引用旧修复回执。该视图没有发送给模型。

修复结果变更时，原审核仍绑定原结果。审核对原答的具体意见可作为修复线索，不能迁移成“修复结果已独立审核通过”。本轮新增独立审核为 0。当前事实、时机意图、自由文字理由、条件方案均不得暗改。
