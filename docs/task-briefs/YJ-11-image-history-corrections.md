## 一、YJ-11 目标与验收定位

YJ-10 已在九霄普通角色卡页实现可审计的视觉触发、普通交谈抑制、现图/参考/审阅独立资格与玩家可知范围过滤。已提交的合成报告记录 14 轮浏览器流程、4 次 mock 发送、错图 `mismatch:people` 被拒、最后两次综合回归 19/19。**这不是用户可回看并纠错的图片历史功能**。

本轮要实现一个安全、简洁且真实可操作的历史面板：

- **能看明白：** 第几轮文字对应哪个地点、视觉版本、触发/跳过/复用/预设/生成/编辑决策；哪个任务发出了哪些尝试，收到了哪张原件，审阅和拒绝原因是什么。
- **能纠错：** 对图片的错误人数、地点、光照、视角、结构等问题记录“反馈→审核/失效→可选的受控替代”，保留原始证据与每次纠错的审计，不静默覆盖原图或改写权威剧情。
- **不乱展示、不乱扣费：** 历史查看授权、当前画面资格、可编辑参考资格分别检查；未知结果不因打开历史、刷新、重复点击而重新发请求。使用 mock 演示替代生成也必须走新纠错身份与合格的真实任务归属，不能伪装成旧结果。

本轮只要求最小可用的历史、审阅纠错和本地模拟替代功能。**不做**整套图片画廊、复杂编辑器、批量素材管理、正式发布、地图、生产对象存储或真实供应商接入；YJ-12 才进一步强化跨终端稳定性。

## 三、模块 A：按会话可追溯的图片历史

创建可信的历史查询模块（例如 `packages/image-history/`，目录可按工程实际命名），在受鉴权宿主提供最小历史列表与详情。建议使用**服务端查询与分页**，不是把整套数据库或源世界书送给浏览器。

### 历史条目最小字段

每条可对账并区分：`scope`（仅服务端）、`revision`、已完成 `source/eventKey`、场景稳定 `sceneId`、`visualVersion`、选择类型与公开可读理由、`taskId`、`requestKey`、`attemptId/ordinal`、`assetId`、审阅状态与审核版本、图片当前可读取与否、来源是预设还是生成/编辑，另有必要的更新时间/状态。对于不存在的字段用明确的 `null` 或“未记录”，**不可伪造远端 ID、耗费、模型或历史回执**。

至少处理：

- `preset` 和 `reuse`：可能没有新任务/尝试，只引用获准资源或旧 asset；复用一张图不应该在历史里凭空新增图片原件。
- `generate/edit`：一项原计划可能有多个尝试；明确失败、refused、unknown、waiting、returned 和被审阅拒绝可分开呈现。
- 同一事件的多次 view/seq/轮询：避免重复显示成多轮剧情；必要时提供可展开的细节而非丢失审计。
- 同一 SHA 的两个资产：按真实 assetId 和各自目标分别展示，不共享审阅结论。
- 旧 08/09 选择行缺少 YJ-10 新的 trigger/evidence 字段：历史详情明确显示“未记录”；不反推伪造。
- 一次历史读取或浏览器刷新不创建图片任务，不触发图片发送或纠错。

分页要有稳定顺序与可靠游标，覆盖至少一个超过一页的样例；顺序按持久事件修订和必要的唯一键，而不只靠可重复的时间戳。

### 历史访问与图片原件

**历史可查看 != 当前可显示 != 可作为编辑参考。** 每次列表/详情/下载都从九霄受信 Cookie 和普通会话路由重新确立 owner/session，并核对同 scope 的数据；绝不信任浏览器提交的 ownerId、路径、asset.scope 或任意导入 ID。

历史元数据可以保留“曾经审阅接受/曾经被展示”的事实，但历史图片字节应经当前访问权、合法资源使用许可和 SHA-256 再检查。撤权/删除会话/错用户后，受保护原件必须拒绝下载（沿现有 403/404 语义）；不得因为加了“历史模式”就绕过 05/07/10 的门禁。历史旧版本可以经单独授权进行只读查看，但**不能因为能查看历史就把旧图提升为当前图或自动参考图**。

## 四、模块 B：可审计的“问题反馈与纠错”

本轮最小 UI 允许玩家标记当前或历史图片：人数错误、地点错误、结构错误、光照/时间错误、视角错误、存在尚未揭示的人物/秘密、其他/无法判断。输入限制长度、字段和大小；不接收能直接写 PG 的任意 JSON，不执行来自图片/世界书的指令。

设计**追加式纠错事件**（单独 PG 表或等效独立事件流），记录至少：独立 correctionId、目标 scope + assetId（如是预设则保存独立句柄与来源标识）、源 revision/sceneId/visualVersion、原 reviewId、反馈类别、受信 actor/权限、被声明的实际问题、证据/判定依据、状态变化、先后顺序、createdAt；保护私人文本/路径/敏感元数据。

必要的行为：

1. 同一用户双击/重复请求同一个纠错指令：依幂等标识返回同一记录，不新增重复纠错或发送。
2. 错用户、错会话、错目标、已撤权或过时版本：禁止冒名纠错他人的原件；已失效原件若存在合法历史访问权，可仅留下有限审计记录，不能重新授予下载或显示。
3. 仅用户反馈不能自动证明图片穿帮；先记录 `reported/pending-review`。受信审核者或受控合成 fixture 的明确审核结果才能改成 `accepted/rejected/invalidated`。**不得把玩家自报人数直接写回剧情 Visual 或成为永久已确认图片事实。**
4. 审核判定要将“历史审核事件”与“当前有效资格”分离。当前 `ImageTasks.review` 会改写 asset.record.review；YJ-11 需补上追加式审核变更流水，先记录原结论和本次依据，再在同一受控事务内更新活动资格。即使当次结果由 accepted 改成 rejected，原始接受证据和字节仍须可查。
5. 同一资产再次改判、并发两次改判或审核时崩溃：不得乱序覆盖审计、丢原结论或出现“数据库判已撤销但页面仍拿原 URL 下载”。明确可回滚的服务端策略；不得删除已有图片原件做不可逆“纠错”。
6. 若发现原图明显不合当前人数、地点、视角或存在未揭示信息，正确效果是**使其不再作为当前图或参考**，文字照常继续。拒绝原因保留到历史，不重写已保存剧情。
7. 同一 SHA 的两个不同资产必须独立反馈/审阅：针对五人任务收到的错三人图，不应因此取消另一次合法的三人场景资产。

## 五、模块 C：可选的受控替代/重新生成

只有在完成基本历史与纠错、安全账本检查后，才开发最小“建议替代”入口。**严禁用旧原任务身份直接重发图片。**

- 对于当前目标已变、待核实、会话被撤权、当前生图关闭、失效图片或供应商结果未知，替代方案必须先返回 `blocked` 或 `requires-review`，不得自动发送。
- 如需要模拟“纠错后再生成/参考编辑”：应创建独立 correctionId 与 replacementRequestKey，明确链接原 assetId、原 revision/visualVersion、父纠错事件以及目标当前 Scene/Visual，记录新的本地 task/attempt/asset 和实际审阅。需以**新的受信任务身份**满足现有任务唯一性约束，不伪造新的九霄已完成正文/同名事件，也不覆盖原任务行。若 0.1.1 契约或 YJ-05 执行模型无法安全表达，则应交付`blocked:contract-adapter-required`及测试，而不是绕过检查派发。
- 替代操作最多可通过注入 mock 验证本地接口；真实图片 API、实际收费、远端查询和撤销均不在本轮。无供应商或无能力时可以保留纠错记录、留空并继续文字。
- 对结果为 `unknown` 的原请求，直到明确有远端核对/用户确认重做策略之前，不允许因为旧图片审阅拒绝而再派同一付费逻辑请求。重启、双击、刷新与另一进程都必须防重。
- 新资产出现时不可立即取代当前图；仍经 pending→受信审阅→可显示资格核验，再按实际当前视图显示。更换场景或迟到后必须停留在它的原历史归属。

## 六、模块 D：最小图片历史与纠错界面

在原九霄普通角色卡中的映界面板新增一个折叠式/可切换的**本会话图片历史**区。允许查看过去已确认的图片节点和状态/原因，以及对有权限的目标“反馈图片问题”；不能打开未经审核/无授权图片原件的可下载直链。

最小 UI 应有：

- 时间线：文字修订、场景名称/版本、使用来源（预设、复用、生成、参考编辑、跳过）、状态与简单拒绝原因；
- 有权限时可查看历史缩略图或按授权显示原件；失效、拒绝、未审和撤权有正确占位状态；
- 纠错表单：选择问题类别并提交，显示反馈已记录/待审/经审阅撤下等状态；
- 如本轮做了受控替代：只在服务端明确允许时出现操作，显示请求状态；未知/失败不谎称已取消或已重新生成；
- 移动窄视口、键盘、滚动与原文字行动同时可用；历史页或纠错失败不得阻断文字。

权限校验在受信服务端；React 不接 PG、不自报 owner、不能通过任意 task/assetId 枚举他人的图片。切换会话、关闭面板、登出、撤权时取消旧视图读取并阻止迟到结果覆盖当前画面。旧历史页面可保留“已发生”状态但不得误当“当前”授权。
