## 二、最高优先级 GATE-0：HTTP 429 与重复回归的可靠性

**YJ-12 当前验收事实：**同一代码第一次综合 22/22；紧接着一次 18/22，四组浏览器检查在访问 `POST /api/auth/code` 时拿到 HTTP 429，因此后续断言未执行。它们不是被证明的产品行为失败，但意味着**本地持续回归尚未稳定**。YJ-13 不得在此问题未清楚隔离前报告「全量稳定通过」。

九霄固定上游的认证源码存在真实限流：`requestCode` 经 `issueIpLimit` 与 `issue`，包含 per-IP 每小时、单邮箱发送间隔及次数、全局发送配额；HTTP `RATE_LIMITED` 返回 429。**源码支持此排查方向，但本次 429 到底命中了哪个限制尚未实测证实。**

### 必做诊断

1. **先定位限流来源：**在**独立合成测试数据**中读取准确的 429 响应、标准错误码、Retry-After、请求 IP、当前测试账号分组和相关限流计数。不要输出真实邮箱、验证码、Cookie、令牌、原始敏感响应或可用于冒名登录的值。区分 per-IP、per-email、全局和并发测试宿主共享数据库；不根据返回 429 就猜是某一种。
2. 分析 YJ-11/12 验证器如何反复创建合成登录用户、是否共用本地认证库或同一源 IP；是否有重复登录、未停止的浏览器或并行验证器、验证码请求非必要重复。YJ-12 已增加 `pg_ctl` 生命周期独占，不代表认证配额隔离已解决。
3. 制定**测试隔离优先**的修复：每次综合回归使用符合授权的全新合成认证测试库/独立测试集群，或通过上游已有合法的测试 fixture/session 建立渠道；如不能隔离则服从限流和 Retry-After，在可验证时间窗恢复后重跑。切勿在共享数据库里随意删除限流表或伪造远端 IP。
4. 不关闭生产认证限流、不伪造来源 IP、不禁用验证码安全逻辑、不改九霄 `main`。如确实需要测试专用接口或限流可控时钟，必须只在隔离测试构建及合成账户环境生效，带显式开关、严格限定入口，记录对安全保障的影响，并让真实认证限流测试继续有效。
5. 把所有综合回归入口统一到有界的测试脚本/验证器，防止同一台机器上无节制地重复调用验证码。失败后给出可理解的「认证环境限流」诊断，而不是吞掉 429、放大计时阈值或自动无穷重试。

### GATE-0 通过条件

- 在可复现的**受控、隔离合成环境**，同一固定提交的完整综合回归至少**两次独立、结果可核对**地全部通过；记录每轮实际测试总数、失败、跳过、授权计数和耗时。
- 至少有一项限流行为本身的正确性测试：实际达到预设上限时正常拒绝，权限隔离无回退；不要为了绿色测试而取消安全限制。
- 若环境仍反复 429，必须保留 `GATE-0: BLOCKED`，附具体已执行命令与失败日志；允许完成其他不依赖此条件的演示文档/离线审计，但**不能把 YJ-13 判定为全量 PASS 或本地初代稳定结案**。
- 原 YJ-09/11 历史偶发超时或测试数据库生命周期问题若重现，明确归类为新回归/已有未知风险，逐一记录；不能直接认定已经排除。

## 三、GATE-1：真实本地浏览器中的连续试玩

在 GATE-0 可用环境内，通过**九霄原有角色卡页面**至少完成一段长于此前独立 13、25 轮案例的连续合成试玩。建议一条约 30–50 个已完成文字修订的主线，和第二个隔离会话作为交叉验证。可由固定脚本驱动，但应保留浏览器实际操作的证据；不能只有单元调用或简单数据库插入就声称玩家能玩。

覆盖的体验应包括：

- 入场与完整视觉事实；普通对话/重复观察没有不必要的生图发送。
- 明确人物到场、离开、当前名单重述、未知指代与保守待核实，重访后人物与地点不串。
- 同名异地、地点改名及别名、昼夜/灯光和视角变化；图像版本与已保存正文逐轮对账。
- 合格预设、合格图复用、模拟动态生成、参考编辑、无能力跳过、错误人数/错误光照审阅拒绝；所有图片都限定于既有获准的三张示例原件，四人无合适图时可留空。
- 图片开关、请求失败、等待、unknown、刷新、离线、迟到、撤权、图片历史、反馈与可信改判；错误旧图 URL 必须失效。
- 历史分页、显示已发生 vs 当前可见、相同 SHA 不同资产，防止回看历史自动派发新图片。
- 切换账户、切换角色卡会话、双标签页与重新打开；前一个会话的晚到结果不能覆盖当前。
- 演练开始前和结束后，核对 completed-history 修订数、YJ-04 状态、视觉版本、YJ-05 任务数/attempt 数、原图摘要、审阅事件及 UI 正文。记录真实 mock sends，**真实模型/图片调用保持 0**。
- 至少保留一段故意超出有限提取器支持的合成散文，显示画面待核实而不是误采纳。最好把语义参考标准与测试输入分离，明确仍是开发自编数据，不能把它当独立人工准确率。

如果连续试玩出现错人、错场景、旧图越权显示、unknown 重发、已撤权图复活或丢失权威文字等 P0 问题，立即标记 `NO_GO`，留下可复现证据并优先定向修复。普通 UI 瑕疵可作为 P2/P3 单独列待办，避免无限扩大首版范围。
