# YJ-01 固定运行基线

## 目标

确认映界新仓库的实施起点，以及九霄已有文字玩法的实际接入与运行路径，为YJ-02和YJ-03提供可靠输入。

## 基线

- 映界：本仓库初始化文档。
- 九霄：已核查提交1bd7bb5ff6e6221378a7cb1292e559fb19bfbfbc，上游https://github.com/L-core-dev-team/Nine-cloud。
- 如果开始时远端发生变化，记录新旧差异并选择明确基线，不静默切换版本。

## 前置依赖

YJ-00已获准启动。先读AGENTS.md、docs/decisions.md、docs/repository-baseline.md。开发副本与现有用户工作区隔离。

## 工作范围

1. 核实完整上游工作副本、分支和未提交改动；需要时创建隔离副本。
2. 按上游说明核查Node、pnpm、数据库与本地会话启动条件。
3. 先验证现有允许的本地流程，再记录真实模型调用所需条件；不复用已经关闭的旧联测授权或寻找凭据。
4. 记录建局、行动、文字保存、重新打开和继续流程的实际结果。
5. 对比角色卡会话与原生权威回合，给出映界接入点建议与依据。
6. 明确Node与Worker运行边界，说明独立映界仓库如何引用或适配上游；不默认为复制全仓。

## 交付物

运行基线记录、现有流程结果、环境差异、接入点建议、YJ-02所需输入和仍缺条件。当前未提供映界业务代码，不应为了制造可运行状态而临时拼装一套无关应用。

## 完成检查

能区分源码已存在、合成流程已运行、真实模型已运行三个层次；记录准确提交；有明确的下一步接入建议。遇到凭据或环境缺失时记录具体未验证项，继续完成可进行的只读核查，不把未知项写成通过。

## 接续

更新docs/repository-baseline.md、docs/verification.md和docs/handoff.md；随后进入YJ-02关键生图能力验证。
