**现在可以直接实现的目标**：在本地 Node + PostgreSQL 环境中，用可注入的模拟图片供应商，把画面决策变成有持久状态的任务、尝试、图片原件、审阅和结果归属。证明重启、竞争、重复请求和结果未知不会轻易产生重复发送或错误展示。真实供应商接入目前缺获准 API 和认证，必须保持 `BLOCKED / NOT_RUN`，不得用模拟结果宣称已经接通。

这不是重复 YJ-02 的内存版 `mockSession`。YJ-02 的请求准备、三张原图和完整记录可供参考；**请选择性读取或移植必要实验逻辑，不直接合并整条 YJ-02 分支及其交接文档。** 此分支继承 YJ-04 的契约修补；若与 02 的 0.1.0 代码有差异，以 0.1.1 为消费基线，新增适配检查。

## 二、必须实现的模块能力

| 范围 | 必须证明的行为 |
| --- | --- |
| 受信输入 | 从 YJ-04 已校验的 ready 场景快照消费 Scene/Visual；not-ready 不伪造地点或安排出图。由宿主验证账户、会话、当前访问权与主动视图许可 |
| 决策与去重 | 消费 `DecisionSchema`，处理 generate/edit/reuse/skip；同一事件重复计划不重复建新任务，有冲突时记录而不是覆盖 |
| 任务持久化 | PostgreSQL 保存计划、requestKey、尝试、状态、来源、实际发出时间和结果；持久索引能够支撑多个进程协作 |
| 模拟发送边界 | 注入本地 fake Provider，能模拟生成、参考图编辑、明确失败、拒绝、发送后未知和迟到。零外部请求 |
| 结果归属 | 使用已有 `resultLink`、`classifyResult`、`displayEligibility`、`referenceEligibility` 等规则，并结合宿主实时授权，防跨账户、会话、地点和视觉版本串图 |
| 资产管理 | 测试期把图片原始字节存到受控目录，保存 SHA-256、大小、格式、存储键与来源；验证读回一致。引用原 YJ-02 PNG 必须注明为既有证据，不算新生成 |
| 审阅与展示 | 模拟返回的资产初始为 pending；只有经已有审阅资格检查后才可能被展示或用作下一次编辑参考。拒绝、矛盾和无法判断的图不强行显示 |
| 恢复与清理 | 重启能读回任务和历史；过时/迟到结果仍归原任务，不覆盖新的当前画面；未知结果不自动重发；孤儿文件、错误摘要有明确处理路径 |

YJ-04 输出的默认 `Decision=skip` 仅表示“场景状态已保存，等待画面规划”，**不能将这个占位决策直接解释为玩家永远关闭了生图**。首批可以用经验证的显式测试计划驱动任务；真正根据剧情自主选择 generate/edit/reuse/skip 属于后续联调与触发策略工作。

## 三、任务、尝试、失败和重试的关键安全边界

1. 用现有 `requestKey` 标识同一逻辑计划，给每次实际尝试分配不同的本地 attemptId。计划、尝试和资产分别持久化；不要把本地 ID 当成供应商远端 ID。
2. **发出外部请求不能与本地数据库事务形成分布式原子操作。** 在真正接入供应商前，先通过状态持久化与注入故障测试明确：进程在“标记准备发出”与“得到结果”之间崩溃时，哪些任务处于可能已发送状态。无法确认是否送达的任务必须 `unknown / hold-unknown`，禁止无凭据自动重发。
3. 只有供应商实际验证支持查询，并取得真正的远端请求 ID 后，才可查询原请求。取消前端等待不等于取消供应商任务，也不能推断没有计费。
4. 本轮可以验证“明确尚未发送”和“明确失败”在显式策略允许时能够重新进入评估；**不要求默认启用自动重试**。真实供应商幂等能力未知，不能宣称跨网络 exactly-once。
5. `reuse` 与 `skip` 不发图片调用；`edit` 必须校验原参考资产真实字节、sha256、审阅状态及归属。旧图不能直接展示时，也可能在满足契约规则后用作编辑参考。
6. 结果回执必须绑定原 requestKey + attemptId，并核对目标画面。重复一致结果幂等记账；内容冲突保留待人工/策略处理。旧任务结果可以记回原历史，但不能抢占其他会话或新视觉版本的展示窗口。

## 四、资产与鉴权边界

本地开发期可采用可替换的文件存储实现，不预先决定生产对象存储。原件保存应采用受控相对键、受限目录、文件大小和格式检查，禁止路径穿越或信任回包中的任意本地路径；先安全落盘与摘要校验，再发布可引用记录。中断造成临时文件、数据库记录与实际字节不一致时，应能够检测并补偿/清理，不能把半写文件当成功。

数据库使用独立的映界任务 schema 或明确隔离的测试存储范围；数据库迁移、公共 API 与根依赖交由集成负责人协调。可复用 YJ-04 的 `pg` 连接池和受信来源身份，但不要让图片模块直接接管九霄权威存档、角色卡鉴权或文字事务。任何给前端的查询、下载、审阅操作都必须由宿主重新验证账户/会话和资产归属，不接受客户端自报 ownerId 作为授权依据。

不得在仓库存放真实密钥、Cookie、私人正文、未授权素材或原始供应商敏感响应。

## 五、必做的定向验证

以少量高价值、可重复的离线/本地测试覆盖：

| 场景 | 预期 |
| --- | --- |
| S0 生成、S1 复用、S2 I0→I1 编辑、S3A 复访、S3B I1→I2 编辑 | 能映射现有酒馆计划，参考链正确；复用不新增尝试，生成/编辑只调用注入的模拟边界 |
| 同一事件并发提交 | 数据库约束与锁防止建立重复逻辑任务 |
| 崩溃前、发出边界、得到结果前、保存图片前后中断 | 重启能识别原尝试、处理残留数据，不凭猜测重发可能送达的请求 |
| 超时与取消等待 | 未知结果保持原尝试；无真实确认不能标记远端 cancelled |
| 原结果迟到、乱序、相同回执重复到达 | 原归属和历史保持；错误当前视图不得被覆盖 |
| 错用户、错会话、错地点、旧版本、撤权 | 不读取或展示其他归属的资产，也不借此发编辑请求 |
| 参考图错误摘要、未接受审阅、被标记失效、文件缺失 | 参考编辑发送次数为 0，并保留可辨识失败原因 |
| 结果费用/用量/供应商 ID 不存在 | 保持 null，不能填写伪造数据或零成本 |
| 模拟图片返回、保存、再次读取 | 文件内容和 SHA-256 一致，来源为 mock/已有测试图，审阅初始 pending |
| 图片模块失败 | 不回滚已经完成的九霄文字回合，不阻断文字继续 |

至少运行一次真实本地 PostgreSQL 的跨进程/中断恢复检查；仅在内存 Map 上通过不能算本阶段持久化完成。测试回执分开记录：静态核查、离线单测、PG 集成、HTTP/权限和真实供应商调用。
