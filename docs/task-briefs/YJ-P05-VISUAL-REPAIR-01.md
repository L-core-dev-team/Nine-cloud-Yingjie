运行时仍从经过鉴权、真实 accepted 回执和已保存正文建立本局绑定。保持 owner/save/branch、请求键、修订、规则/内容版本、正文摘要及规范化回执摘要的完整来源链。若需要事件中的目标、结果、线索 ID 等字段，从该次原生回执提取必要白名单；不能只凭一个格式正确的摘要或前端自报获得资格。

**验收路线只用于测试，不能作为运行时的前序白名单。** 不读取 A/B/C 的路径名、绝对回合或未来回合来决定出图。相同地点或正文摘要也不能单独放行；无关的奖励条件可以解除，归属、版本、当前依据与反证校验保留。

### 2.1 当前观察、上次所见和无图分别记录

新观察满足条件时，建立该回合的新绑定，可使用同一原件。若该局以前真实显示过同一图，记录复用；尚未显示过则记录首次展示，不能把素材预先存在算作玩家看过。

普通闲谈或领奖可以在持久条件明确成立时保留上一张图：

- 仍是同一存档、地点和允许视野，没有移动、子区域变化、相关物件变化或冲突；动作类型及原生后果明确支持这种保留。
- 图来自本局可追溯的有效观测且实际显示过。保存原观测修订，不用最近一次“保留”的修订冒充重新观察。
- 连续多次保留可追溯到最初观测，例如清障 → 闲谈 → 领奖，均标“上次所见”，不因插入闲谈断链。
- 一旦离开地点、进入另一子区域、出现反证或不能判定的行动，保守收起。后来仅抵达旧地点，不能自动把历史画面当当前；新明确观测可以恢复资格。

重复 scan 的 none 文本不能登记为再次确认开场景物。本轮可以按明确连续条件保留旧图为“上次所见”，也可以收起；选择须固定并说明依据。A2 的 move.blocked 只说明尝试未成功，不得登记移动成功或已重新确认南望，本轮默认收起当前图并保留历史。

### 2.2 明确处理先清障后首次察看的冲突

固定上游允许先清障，再第一次获得旧淤船线索。执行者必须保留实际正文与回执，并记录这一“原生清障状态与观察文本不一致”的来源问题：

- 已清障的规则状态优先用于拒绝不合格图片；不能让 I01 覆盖成仍在清障前的表现。
- 可从本局已授权公开规则后果判断，或增加最少的受权 ferryState/obstacleState 投影及来源；不导出整个内部存档或隐藏设定。
- 不自编“船已靠岸”的正文，不修改上游规则，不改原回执或旧实验结果。冲突回合保留文字，图片收起，诊断记录冲突原因。
- 对用户只显示必要的无适用图状态；详细字段放诊断区，不把实现问题写成新剧情。

这项负例是新适配器的拒绝能力，不要求本轮修掉上游叙事问题。另在报告中留一条明确的后续问题即可。
