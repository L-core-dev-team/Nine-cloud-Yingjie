## 1. 要回答的产品问题

在可靠程度明确的场景候选与截至当前的剧情前缀上，AI 能否区分：

1. 当前事件有清楚、值得呈现的可见结果，适合提出画面更新建议。
2. 当前剧情很重要，但主要意义靠文字表达，画面不必跟着更新。
3. 只有微小变化、重复描述或未兑现计划，暂不追图。
4. 当前可见证据不足，应该等待或保留待审。

重要性、可视价值、证据充分程度、节奏理由由 AI 判断；程序负责输入隔离、结构与证据绑定、引用时点、状态与权限边界、去重和可重放。不要再建一套按关键词、特定人物、修订号或故事名称判“高潮”的替代算法。

**内容建议与执行结果分别记录、分别评价。** 本轮执行层全部阻断；不能把阻断统一改写为模型的 text-only 意图，也不能用“零派发”证明时机判断已经通过。

旧策略的 14 个 text-only 与 S2 全 not-ready 保留为历史现象。`stability/policies.mjs` 把原剧情送入旧 S2/H2/H3 路径，没有直接消费 STABILITY-01R 修复投影，不能把它当作与本轮同输入、同门禁的纯语义胜负比较。

## 3. Gate A｜隔离评价信息，冻结输入与协议

### 3.1 旧十四回合只能经白名单清洗后入模

原 `timing-input.jsonl` 同时保存候选与评价信息，**不能整行直接发送**。使用显式字段白名单及嵌套结构转换，原导出保持原样。至少隔离以下内容至仅供评价使用的目录：

- `authorTimingBaseline`、`fixedBasicFieldScores`、`previousExperimentPolicy`。
- `expressibility.originalAdapterDiagnostics`，包括已修复问题的旧拒绝码。
- 原审核答案、通过/失败分数、作者期待动作、已知目标回合的判定、任务书及报告。
- `source.action` 等人工回合标题不进入候选题包；正文、scope 和真实修订号保持不变。

允许进入模型的内容如下，必须保留其来源与不确定性：

| 内容 | 要求 |
|---|---|
| 当前正文与必要前缀 | 只到本轮，原文不改；不得带下一轮或全故事后文 |
| 当前字段、物件属性与未知 | 保留字段级状态和引用；候选值不是权威事实 |
| 历史最后获证值 | 明确标为历史及其修订，不能补作当前属性 |
| 可见变化、观察差异、首次获知 | 分开保存；同一证据重复出现在多个列表不能重复计算重要性 |
| 承诺、条件、当轮后果与关联候选 | 保留 conditional / needs-review 等状态，不能强行确连 |
| 遮挡、回忆、转述、假设等限制 | 可作为理解剧情的上下文，不能直接作为当前画面事实 |
| 覆盖审核状态 | 真实的未独立审核状态，不能继承旧审核为新候选背书 |
| 参考图与展示状态 | `none-established`；本轮未生成、持有或展示可用剧情图 |
| 先前时机建议 | 仅本轮实验中已真实归档的上一轮建议及校验状态，明确是建议历史 |

可见性/未知信息从准入字段机械派生，不能从作者评分反推。摘要变化不等于现实变化，候选“可表达性”也不等于正式 S2 就绪。输出被剔除字段的清单、清洗版本和输入哈希；对不在白名单内的新字段默认拒绝。

模型也可依据当前原文发现上游列表未充分表达的含义，但只形成新的时机解释与引用，不回写场景状态。例如 R13 的签字动作不能因为上游 `visibleEvents` 为空便被宣称完全不可见；其权益后果也不能因此变成可直接看见的物理状态。

### 3.2 一条新的六回合剧情

由本轮执行者编写一条自然、连贯的合成修仙短剧情，恰好 6 回合，约 1–2 个地点、2–3 名稳定人物。不要另开模型对话写故事，不只替换旧故事人名与“水簿/开闸”词汇。事件结构、呈现次序和关键物件应与旧篇有实质差别。

六回合合计覆盖：

- 一个证据明确、确有画面表现价值的结果。
- 一个安静但有重要直接后果、文字承担主要意义的节点。
- 普通可见小变化和相邻回合的延续，使连续追图不是默认选择。
- 一处重要内容暂缺可见证据，之后有足以推进判断的观察。
- 回忆、转述、假设或未来提议与当下发生事项的区别。

这些因素可自然合并到同一回合，不要写成六道模板测试题，也不要求新篇重复完整状态稳定性验收。

为控制变量，可人工准备最小“来源事实夹具”：正文直接支持的当前事实、未知、限制及历史引用，统一成同一输入接口，来源明确为 `author-supplied-source-fixture`。夹具只含事实与不确定性，不含重要性、画面价值、期待动作或剧情节拍标签；不调用新场景抽取模型，也不将作者整理计入模型识别准确率。本轮新篇结果只说明给定这种输入条件下的时机判断表现。

### 3.3 冻结顺序与可见范围

在第一份候选请求前，提交并记录正文、来源夹具、评价金标、通用提示、schema、清洗/题包构建规则、审核槽位、验收断言和预算。评价文件与模型可读文件分离，公开回归与新篇分组计分。

逐轮标签采用“可接受动作集合 + 必需理由/证据 + 不允许的事实断言”，允许有依据的审美分歧，不用每回合唯一 new/edit 标签代替判断。对新篇预先指定视觉关键点 V、安静关键点 Q，以及小变化/遮挡/延续的检验点；这些标记仅评价者可见。至少一个小变化/延续检验点要求不新增图片建议。

候选只收到通用提示和当轮清洗题包，不读取本任务书、完整仓库、评价文件、审核结论或未来剧情。优先使用不继承主对话历史、只具备当轮输入的独立对话/隔离工作目录；记录实际可读范围和调用方式。只有口头“不要看答案”而无法确认隔离时，不宣称盲测通过。

新篇可称“对候选上下文未公开的六回合检验”，必须披露作者、提示设计者和金标评估者是否相同；不能称独立外部盲评或广泛泛化证明。

因题包包含真实先前建议，不能预填整条理想建议链。先冻结构建器与静态来源，再按首答归档顺序生成动态题包，记录前一建议/题包哈希。跨组不共享建议历史。

## 4. Gate B｜通用判断协议与输出

### 4.1 模型只负责研究建议

通用提示解释以下概念，但不出现旧 R9/R13 答案、新篇 V/Q 标记或样本专用规则：

- 剧情重要性：当前行动/信息对人物目标、关系、资源或结果的意义；重要不必表现为大动作。
- 可视价值：本轮真实可见结果能否让一幅静态图提供有用信息；动作词、微小属性变化、首次得知和故事重要性不能互相替代。
- 证据充分程度：只针对拟表达的具体焦点判断，列出实质未知；不因无关字段缺失把一切降为不可表达，也不把局部可表达写成完整场景就绪。
- 节奏：参考此前真实建议与当前新增内容，避免重复建议同一结果或追逐每个小变化；没有真实图片时，不声称已经看过上一图或测到实际展示间隔。

冻结最小 JSON schema。字段名称可在第一请求前调整，含义不得合并；建议结构如下。表中枚举不是样本答案：

| 字段 | 内容 |
|---|---|
| `scope / revision` | 与题包逐字绑定 |
| `narrativeImportance` | low / medium / high / unknown，简短理由及证据引用 |
| `visualValue` | none / small / clear / unknown，简短理由及证据引用 |
| `visualReliability` | sufficient-for-focus / partial / insufficient / conflict，拟表达焦点所需的实质未知及限制 |
| `timingIntent` | update / text-only / defer / needs-review |
| `cadenceReason` | 为什么此刻更新、保持文字或等待，与历史建议怎样相关 |
| `conditionalPresentation.withoutReference` | new / text-only / defer / needs-review |
| `conditionalPresentation.withSuitableReference` | edit / reuse / text-only / defer / needs-review |
| `conditionalPresentation.requiredReferenceConditions` | 编辑/复用需要的同场景、机位、当前事实与权限等条件；不能断言这些条件已满足 |
| `focus / excludedFromImage` | 少量有依据的拟呈现内容、必须排除或不确定的内容；不写完整美术或生图提示词 |
| `evidence` | 截至当前的修订号与唯一短引；程序定位并附正文哈希与起止位置 |

枚举之间须一致，例如 timingIntent=update 需要可见结果或新场景建立依据，不能同时表示毫无证据且无需等待。text-only 表示本轮文字足以承担主要表达；defer 表示有待满足的证据/时点条件；needs-review 保留冲突或无法判断。

`conditionalPresentation` 仅为明确假设下的建议，**不是虚拟资产、模拟派发或授权凭证**。本轮实际无已确立参考图；没有参考图不能直接 edit/reuse。若条件缺失，回答条件性分支即可，不制造 assetId、版本事件、图像哈希或展示回执。

### 4.2 程序单独写执行层

模型不能签发世界权威、场景资格或执行授权。程序附加真实固定状态：

```json
{
  "tag": "AI_SCENE_PROPOSAL / RESEARCH_ONLY",
  "referenceStatus": "none-established",
  "sceneEligible": false,
  "actualAction": "blocked",
  "send": false,
  "dispatchAttempted": false
}
```

语义评估读取未被执行层改写的 `timingIntent`，执行核验读取上述状态。保留模型原答、解析结果、程序接受/拒绝及理由，不用程序重写语义答案。

`previousRecommendations` 记录真实建议及是否有效，不得命名或使用为 `lastImageShownAt`、`lastSuccessfulEdit` 等不存在的展示记录。即使上轮建议 update，本轮也不能因此认为已有新图可复用。本次不验证真实生成耗时、图像适用性或展示后的玩家节奏体验。

## 5. Gate C｜20 份首答与 4 个独立审核槽

1. 按回合依次调用旧篇 14 次、新篇 6 次。每轮独立初始上下文、同一冻结通用提示，原样保存首答后再校验；不把整篇一次发送并要求输出所有答案。
2. 每个槽位仅一次尝试。失败、格式错误和送达未知均留证并计数，不追问修 JSON、不改题重抽、不从多个候选挑最好。若上轮无有效建议，后轮输入如实标记缺失，不人工补上正确历史。
3. 四个审核槽固定为旧篇 R9、R13，以及新篇预先确定的 V、Q。审核者独立于该候选的上下文，不继承主执行对话；只看对应前缀、候选题包、实际首答与程序处理结果，不看金标、目标标签或预期错误。程序处理结果仅指结构、引用与边界校验，不含金标比对分数或期待动作。使用同一通用审核提示，逐项核对重要性、可视性、证据、节奏及条件建议，提供原文依据。
4. 每个审核最多一次，不把审核当补答或替换首答。审核绑定 prompt、packet、raw 和结果哈希；其他回合及场景字段仍注明未获该类独立审核。审核后若机械修复改变了被审核结果，旧审核仍绑定旧结果，不自动迁移；新结果不满足所需审核覆盖时记 PARTIAL，不突破预算补审。原 STABILITY-01 四份审核不适用于本次时机结果，新时机审核也不等价于修复场景全字段审核。
5. 预算单列候选 20 槽、审核 4 槽与失败/未知/未运行；任何未执行项不能记作 0 错误通过。只使用合成资料与批准的既有订阅能力，不发真实玩家数据。

编写代码的主执行对话不是实验首答；不能在主对话中预演各轮答案，再把这些答案当独立模型实测。故事、提示或金标冻结后出现模型表现问题，保留原结果，不继续调提示直到通过。
