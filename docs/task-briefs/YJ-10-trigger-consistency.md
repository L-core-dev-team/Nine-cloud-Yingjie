## 三、模块 A：选择“何时需要一幅新画面”

对已鉴权的普通角色卡 `completed-history` 和 YJ-09 已确认场景状态实现最小触发/抑制策略。建议在 `packages/first-play/` 增加隔离的 `trigger` / `consistency` 小模块，或在现有 `chooseFrame` 前加可替换策略层；不建新的完整工作流框架。

触发和抑制应至少区分：

| 事件类别 | 期望行为 |
| --- | --- |
| 初次确认可见的新地点或显著新视角 | 可以考虑预设/生成，但必须已定位、已知且拥有完整可见事实 |
| 人物明确增减、场景结构、时间/光照或视角实质变化 | 原图不符合当前 Visual 时必须失去当前显示资格；可以考虑编辑/生成新版本 |
| 仅普通交谈、动作与无视觉变化的剧情推进 | 优先复用合法当前图或跳过；**不能每推进一个文字修订就生一张图** |
| 明确剧情高潮或用户希望强调的视觉时刻 | 只有当提取器给出可审计的已确认事件/特征时才提高出图优先级；当前规则识别不到时保守标记 unsupported，不从原始小说随意推断“高潮” |
| 图片关闭、地点不明、人物去向含糊、未完整核实现场 | 不发送新图，不显示可疑旧图；文字正常继续 |
| 旧任务 waiting、unknown 或 review-pending | 尊重原请求记录和恢复策略，不因又来一轮文字或刷新重发 |
| 上游供应商无能力、预算/授权不明确 | 允许 skip / no-image；不得虚构价目、远端取消或已确认零成本 |

实现应记录 **triggerCandidate / reason / evidence / suppressedReason / chosenAction**，来源关联 `scope + sceneId + visualVersion + completed source`，并区分“技术上可生成”和“按剧情应该生成”。普通对话可继续显示同视觉版本的老图，不意味着必须建立新请求。不要因触发器在新版规则中被重算而重新派发此前可能送达的图片尝试。

本轮允许采用确定性的少量触发规则和合成高潮标签来验证接口；如没有获准真实语义模型，不能声称已能自动判断任意小说高潮。产品要求仍是“剧情优先、可手动关闭生成、宁缺毋滥”，不要自行冻结未定的具体触发比例或预算阈值。

## 四、模块 B：当前画面、参考图和审阅三层一致性

复用现有 0.1.1 共用契约、YJ-05 图片任务、YJ-07 预设授权与 YJ-09 待核实状态。**至少保持三层判断分离**：

1. **资产审阅是否接受**：图像字节/摘要、来源、审核依据、可见元素是否满足已记录标准。摘要一致本身只能证明文件未变，不能证明画里人数、位置和秘密一定正确。
2. **当前是否可展示**：重新检查当前用户/会话、稳定地点、视觉版本、现时人物/特征/时段、视角、世界书授权、文件完整性、视图许可与迟到结果；错误归属返回不可展示而非拿旧图顶上。
3. **是否可用于下次编辑参考**：即使旧图不能作为当前图，仍可能在符合参考资格时用于从 V1 编辑到 V2；不能因为原图“以前显示过”就无条件使用，不能把未审/失效/错误归属的图片作参考。

要求明确能解释拒绝原因，例如 `different-scene`、`visual-mismatch`、`unknown-visible-state`、`unreviewed`、`stale-grant`、`damaged-bytes`、`wrong-scope`、`prior-attempt-unknown`。如上述是内部示例而非现有导出常量，使用最小适配映射，不擅自修改公共 schema。

对 09 中位置可确认、名单尚待核实的场景，必须阻止旧图/已审预设的回退显示与未经验证的生成。后续完整调查恢复时，读取正确快照和资格，不凭空认为以前图仍是现在画面。

额外记录**人工或显式审核的事实对照**：给本地测试资产加一份与原件相关的独立、可审计的可见元素清单和判定依据；不修改已有三张 PNG，也不要把开发自写标签说成独立图片模型验证。没有真正的视觉语义检测器时，标注内容是测试 oracle，不宣称自动看图能理解错误。

## 五、模块 C：世界书与玩家可知范围的隔离

世界书可以提供地点候选、已获准结构标签，但**不能取代已发生的剧情**。已保存正文是当前事实依据；角色卡导入、世界书、NPC 背景和图片本身都不应该主动新增剧情事实。

必须证明：

- 世界书里预先写有密室、暗门、未揭示宝物、潜伏角色或未来事件，但已保存剧情尚未揭示；它们**不能进入当前 Visual、动态生图提示、预设选择标签或前端可见图片**。
- 世界书的作者说明或角色卡内容若包含“忽略安全规则”“强制生成隐藏人物”等伪指令，只作为不可信文本资料，不能影响宿主授权、触发策略或审阅。
- 引语、回忆、传闻、玩家计划、梦境、第三人称旁白和当前玩家视角的事实保持区分；玩家未实际看见的人物不能仅凭全知旁白被画进玩家视角画面。
- 同名异村、场景改名与重访均沿用稳定 `sceneId` + 有权来源，而非靠名称匹配合并；撤权后旧资源 URL 仍受保护。
- 若本轮构建动态图片提示信息，只从已通过现时事实过滤的 Visual + 有权且已揭示的资料白名单组成，不能直接串接私人完整世界书、原始不可信文本或未经筛选的“秘密字段”。
- 确实需要剧情新揭示的内容时，仅在完成并保存的正文、玩家可知标记和当前已确认视觉变化提供依据后才进入画面候选。提示里包含哪些依据应能审计，但不能泄露私密原文。

测试用的合成世界书与“秘密/未揭示”标签均要明确标注；真实私人世界书未获准时保持 NOT_RUN。不得为了跑测试从万卡阁、Discord 或其他私人资源库自动抓取内容。

## 六、模块 D：触发与审核联动、最小 UI 反馈

保留原九霄文字输入、历史和保存路径，额外在映界面板显示适度、非敏感的画面状态与理由，例如“沿用当前画面”“人物变化，画面待更新”“现场不确定，暂不展示”“缺少合适素材”“图片待审”。不把内部敏感世界书原文或用户身份标识暴露给浏览器。

在本地受信宿主中通过同一视图端点消费决策。统一检查旧回执/异步结果和当前授权。若前端关闭或切换视图，不能把取消本地等待误写成供应商确认取消。未审图可以存历史但默认不可展示。重点维持“文字可以继续、图片可缺省”。

在不引入付费图片调用的情况下，用可信测试 fixture、YJ-09 25 轮与 65 段合成语料补充少量高价值正反例。至少运行：

| 不每轮生图 | 相同 Visual 的多轮普通对话不增加新发送；明确变化且可信时才进入候选 |
| 触发正确抑制 | 人物变化、地点变化、日夜变化、视角变化；含糊人物、未就绪、关闭生图、无授权、无 Provider 均说明原因 |
| 同视觉无双重账单 | 同一视觉版本同内容、同一未知尝试跨刷新/跨进程，不能因为再次触发自动发第二笔 |
| 视觉三层资格 | 图可审阅 ≠ 可当前展示 ≠ 可编辑参考。错版本旧图可以在合法场景下作为参考；未审/坏图/撤权不可展示或参考 |
| 穿帮和隐藏信息 | 不符合人数/结构/时间/视角的显式审阅样例拒绝；世界书密室/未来 NPC/隐藏身份不进入可见计划和提示 |
| 文本时态/视角 | 现在、回忆、传闻、引用、计划、玩家未知事实，分别对照接受/放弃；不把负例写进世界状态 |
| 多地点/跨账号 | 同名异地、别名、不同 session、旧资产 URL、撤权、删除会话保持隔离 |
| 浏览器完整链路 | 原角色卡页面、已完成文字 HTTP、PG、画面计划、mock 任务与前端能够走通；错图宁可留空 |
| 并发/失败/重启 | 同一请求多端并发、结果未知、晚到、重复回执、刷新与重启时展示与发送资格一致 |

对于语义图像审核，本轮只允许清楚标注的 fixture 元数据和人工显式 oracle；若没有新增真实图像视觉检查，必须写明“只是规则/标注对照，并未验证机器自动识别穿帮”。如果原本并行回归有间歇性超时，不能声称“复测 1 次通过就彻底消除”，应报告复现次数、触发条件和剩余未知。
