## 3. 工作包 A：核实两条完全不同的真实模型接入线

### A1. 文字剧情模型

九霄固定上游存在受信 `CardModel` 类型：

```ts
type CardModel = (input: CardModelInput, signal: AbortSignal, call?: ModelCall) => Promise<string>
```

`CardModelInput` 包含系统指示、角色卡、与会话关联的世界书、历史、动作、messages、可选 persona。身份应该由现有 Session resolver / `CardModelAccess` 提供，不能从卡片文本伪造。YJ-08/09/13 所谓“从已保存正文提取”是**读取模拟文字服务生成并由九霄保存的文本**；不等于真实自由剧情模型已接入或任意中文小说被正确理解。

请核对并记录：

- 九霄当前是否存在可被授权复用的文字模型网关/已有 Provider；具体在哪个隔离代码路径，实际支持什么，哪些运行于 mock、哪些尚未运行。
- 若选择真实文字提供商，怎样在**受信服务器**以既有 Session / owner、超时和取消机制调用，不把世界书指令当成宿主命令。
- 原文/世界书外发最小化：只有用户明确批准的文本和许可范围可发送；默认用合成 fixture。避免将全部历史与私人角色卡无条件送到供应商。模型结果仍需先保存为 completed-history，之后才由映界消费。
- 模型输出偏离有限规则时如何产生可审计的提取/abstain，不由图片结果修正文字事实。对通用中文与高潮判断必须独立评测，现有 65 条开发自编语料不能替代盲标。

**P01 可交付的是接口核查、参数清单、零网络 fake client 契约与错例；真实文字服务调用仍 NOT_RUN。** 不提前选定未经用户确认的型号。

### A2. 图片生成与参考编辑

现有 `ImageTasks` 的 Provider 边界具备 `capability` 与 `send(claim)`，YJ-05 持久化 task/attempt、receive、pending 审阅、原件摘要及恢复。当前 `TavernProvider` 和参考图库仅返回三张已有 PNG。YJ-02 的工具级图片生成**不是**可以直接嵌入九霄后端的已授权图片 API。

请整理可在确定供应商后填写的**能力清单**：

| 项目 | 需要真实验证 |
| --- | --- |
| 生成和参考编辑端点、版本及模型名 | 是否开放服务器端 API、是否支持需要的参考图片编辑 |
| 认证 | 服务器端受信凭据配置、权限范围、失效处理；密钥不得出现在 Git |
| 输入 | 画面尺寸、宽高比、参考图编码/上传形式、最大文件/提示长度、允许使用的原件 |
| 结果 | 同步字节还是异步 job、返回原始文件或可控下载、内容类型和尺寸 |
| 任务身份 | providerRequestId 是否真的存在、是否支持查询、取消、幂等键、重试语义 |
| 费用与控制 | 真实计费单位、报价和来源、失败/取消是否计费、单次和整次试点预算硬限额 |
| 输出审核 | 原件 SHA 与 PNG 基本检查 + 独立语义审阅，不把“摘要正确”误当“人数必正确” |
| 数据合规 | 供应商条款、素材版权/外发授权、保存与日志脱敏、不让私人世界书和未揭示秘密进入提示 |

**没选供应商或没核对官方文档时：全部写 UNKNOWN / UNVERIFIED，不编造现价、端点、同态输出或幂等能力。**

## 4. 工作包 B：离线适配层与费用/数据门禁

允许设计或实现**纯本地无网络的**最小适配与验证。建议小模块 `packages/provider-readiness/`，按项目实际目录决定，不为未选供应商引入 SDK 或重写任务队列。

必备验证：

1. **默认拒绝发送。** 未配置被批准的 provider、未通过本会话授权、缺单次/总次数或预算上限、素材缺外发许可、referenceEligibility 不通过，适配入口不得跨越真实网络边界。
2. **显式数据最小化。** 从可信 `Visual` 及获准公开/已揭示标签生成图片请求，不直接拼接完整未经审核的世界书或秘密；未获准的内容连 fake 的请求记录都不应进入。
3. **预算与并发门禁** 只针对未来真实调用：记录请求授权/计数与可能已送达状态，明确“无法仅靠本地计算保证供应商最终账单”。需要真实报价时留空，不以固定 0 元伪造费用。默认关闭所有真实发送功能。
4. **结果未知 / 失败** 分离：发送边界后无远端确认的任务保持 unknown，刷新与重启不自动发第二次；查询和取消只有协议真正支持时才出现为能力。
5. **原件与归属** 由 YJ-05 保存，图像初始待审；错误会话、错视觉版本、审阅拒绝、撤权都不能展示或用于参考。
6. **真实图片尺寸和编辑规格** 不根据已有三张样例推断任意场景成功；资源许可保留来源和用途。
7. **纠错替代** 与原 eventKey 唯一约束冲突。YJ-11 仍 `blocked:contract-adapter-required`；P01 只审阅可行的 `correctionId + replacementRequestKey` 设计和迁移影响，不允许伪造新 completed-history 或自动把它接到真实收费请求。
8. **已有模拟演示不回退。** 原 YJ-13 任务、历史、正文、项目分支全部保留；新增离线测试不能改变现有 mock 的默认意义。

如果构建适配器无意义地依赖特定供应商协议，就提交接口和测试而非硬写一个猜测的 `fetch` URL。明确哪些测试是 static、fake contract、PG、HTTP/Chrome，哪些没运行。

在任何真实调用之前，需由道主明确批准并记录：

1. 提供商与具体模型、API 文档及后端调用权；
2. 使用受信方式配置凭据，不在聊天、GitHub、测试日志或浏览器源代码粘贴密钥；
3. **可以发送哪些**合成故事、世界书摘要和 YJ-02 参考图；图像生成权不自动等于对图像二次外发或商业复用权；
4. 严格的单次请求数、总预算、发送前停止规则，以及不能确定取消/计费时的处理；
5. 预期的审核方式、数据保留/删除要求和负责审核者；
6. 是否明确允许请求到真实端点。未批准前 **PROVIDER_LIVE_CALLS = 0**。

供应商选择、费用细节和密钥方案原本是后置项：只有当用户愿意进入真实试点时才需要收集；**本轮不要求道主回答一长串技术问题，也不把它们默认为已确认决策**。
