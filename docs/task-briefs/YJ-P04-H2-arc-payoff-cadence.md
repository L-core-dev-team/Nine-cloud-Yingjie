## 2. 工作包 A：跨句/跨回合的事件、权益与后果关系

### A1. 事件结构和可追溯性
定义紧凑的 `NarrativeEventV2` / `ArcAnchor` / `PayoffCandidate`（具体类型遵守当前 package 风格）：

- 一件事必须包含事件主体、受影响人物/物件、行动、目标或权利类型、事件前状态、观察到的事后状态（可能没有）、原始修订/sourceKey/正文 SHA-256/UTF-16 半开区间、判断是否当前已发生、可知性和不确定原因；
- 在**受信完成历史**中可核的句子是全部事实来源。把“剧情重要性解释”与“源文本确实声明该事实”分开存储；
- 在不确定、传闻、对白、回忆、计划、假设、讽刺或跨人物指代不明时，必须拒绝进入确认状态。用户 action、图像模型、未经揭示世界书、旧图片不能补证；
- 类型覆盖承诺/约定、等待、目标、障碍、选择、成本、归还与赠与、拥有权/控制权/使用权的转移、继承/共同拥有、关系变化、失去/牺牲、战局/通行改变、发现真相及可信撤销；**不要以字符串命中就自动当成结果已经生效**。

### A2. “渡船”漏判的系统性修复
建立抽象的 `rights-transfer / durable-status-change` 关系框架（可命名）：
- 原控制人/受益人、目标权益、声明者、受让者、动作证据、**结果是否确认为生效**，至少跨句合并；
- 区分持有凭证、代为保管、临时借用、合同签署但未生效、口头约定、伪造文书、登记错误、撤回权利、权益真正变更；
- 正向例子不限船契，必须跨土地/宗门令牌/家产/债务/秘境开采权/居所钥匙/祭坛管理权等独立实体；
- 要特别留意“动作发生，但并没有造成相应权益转移”的硬负例；
- 不允许把“某人把东西递给某人”当作权利更替；必须有明确结果、权利主体与上下文约束。若仅可怀疑有转移，输出待核实事件而非导演候选。

**H1 原 `渡船` 作为公开回归样本；新独立锁定语料要用不同物件和句式。** 与 H1 原 66 项结果做 A/B 对照，不能修改它们的标签或抹掉旧漏判事实。

## 3. 工作包 B：故事线记忆、兑现识别和长期排序

### B1. 版本化 Arc Memory
开发**独立进程内/只读回放**故事线状态图：

- 同一个 scope/session 以内，按已保存回合顺序将 goal → obstacle → commitment/foreshadowing → cost/turn → confirmed outcome/reversal/abandonment 串成有类型的事件边；
- 事件锚点包含角色、对象、目标、可证关系；只凭同一个人物或同一个地点不得认定因果关系；
- 支持至少两条交织故事线、跨 8–30 修订的远距离兑现、长间隔后的错误指代、假兑现、已经撤销的目标与被更正的阻碍；
- 规则处理同名异人、同一人别名、目标转移、新旧拥有者与延迟效果。身份不能唯一确认则停留 unknown，不能自动合并；
- 每个候选必须是**截至当前修订**才能看到的东西，未来修订不能影响过去的排序、原文证据或出图决定。禁事后“预知高潮”；
- 重开后用相同已授权前缀纯回放应得到完全相同事件 ID、图边和排名。若不引入 PG，此处只可判 `OFFLINE_REPLAY_PASS`，不能宣称持久生产状态完成。

### B2. 动态重要性与多候选比较
设计可解释的 **`highlight-ranker/2`**：
- 评分分解：目标兑现、后果持久性、人物代价、关系质变、伏笔时距和兑现强度、转折/逆转、是否实际结束、与既有高峰的相对落差；单纯场面激烈或形容词多不直接加权；
- 使用同一故事线、最近 4–8 回合、当前已知全部时间线的不同比较窗口，保留各自排名与候选原修订；必要时采用事件线归一化，避免长线因事件多而总被压制；
- 不能把分数当成经过校准的概率，也不能自动将“场面高强度”当成“必须生成图片”；
- 多峰剧情必须允许先有小转折、后有真正兑现；若最后一回合只是重述先前结果，不创建新的高光；
- 报告 recall、precision、top-1、top-k、pairwise ordering、误报类型、安静高光子集及跨线排序；特别对比 H1 的 15/16 与 10/11，不能只给总测试通过率。

## 4. 工作包 C：视觉呈现时机与避免同质化的“少而精”

新增 `highlight-cadence/1` 或类似**仅建议、不实际发送**的时机策略：

- 输入：经 H2 验证的高潮候选、候选所在故事线、已处理的高光指纹、最近已出图/已提案的视觉主题、S2 的 `visual-consistency/1` 当前证据及 I1/I2 的任务/授权现状；
- 输出最少三种行动：`text-only`（剧情价值高但没有合法可见的具体瞬间）、`director-review`（值得研究镜头且当前视觉证据充分）、`suppress-duplicate`（同一兑现/同一视觉目标的重复提议）；另可使用 `defer` 表示当前事件还未结束但后续可能有已保存结果，**不得用未来信息提前放行**；
- 刻意设计不会固定每隔 N 回合出一张、不会所有修炼/战斗都触发、也不会在高潮真正兑现之前因为铺垫已加分而连发；
- 同一高光重复改写、两个相邻回合回顾同一结果与仅局部文字变化：最多一个导演候选；两个因果独立的真正关键事件即使时间接近也允许分别进入审核，不可绝对冷却误杀；
- 连续的镜头/主题重复要记录**候选表现意图**，例如动作/静态人物关系/环境大变化/克制情绪，不直接生成默认构图、套用统一滤镜或强制不同“炫光特效”。这只是为 D1 视觉导演准备输入，**本轮不生成 prompt 图片、更不触发图片 API**；
- 即使 H2 认定剧情是高潮，若未独立核实 scene/visual、人物完整名单、光照/地点、参考图许可，必须 `text-only` / `needs-review` 而非跳过 I1/I2 资格门禁；
- 关闭出图仍可识别重要剧情并记录原因，但不产生 pending 真实发送；下次开启不能偷偷重发历史不确定任务。

## 5. 工作包 D：先锁定不同于 H1 的评价集，再开发规则

在新增识别逻辑**之前**单独提交带完整 SHA 的新数据和分组，随后不改标注以追求全绿。建议至少 **160 个新修订，覆盖不少于 24 条故事线**；尽量涵盖修仙、日常和跨题材表述以抵御词表过拟合：

- 至少 50 个 ordinary hard-negative：虚张声势却无结果的打斗、反复叙述旧高潮、同地点无因果的闲谈、假发证、临时保管、假权限转移、未实现计划、传闻/梦境/否定；
- 至少 20 个安静高潮或确定关系/权益变化，含无“终于”“震撼”等情绪词；覆盖与 `渡船` 不同实体和语言；
- 至少 16 个跨 8+ 回合铺垫/兑现与撤回，至少 6 组多故事线交织和同名歧义；
- 至少 12 组“事情重要但画面没有足够证据” vs “画面可见变化但情节普通”的成对对照；
- 至少 12 组相邻重复/持续战斗/两次独立重要事件的时机与去重例子；
- 通过同一个 source prefix 的有/无前文对照，强制 H2 不能仅靠当前句式判断（例如普通递交 vs 权利已改变）；
- 组别按**整条故事线**划分 dev/held，预留组不少于 40% 的修订；标签冻结 commit 与模型/规则实现先后顺序必须有据可查。
- 若能邀请独立标注者，记录双人分歧和仲裁；否则明确写 `INDEPENDENT_HUMAN_BLIND_REVIEW_NOT_RUN`，不要将作者自标冒充外部人类评审。

各样本至少需金标：事件类型/参与者/前后权益或关系、关键高光修订及类型、证据 spans、依赖的先前修订、跨线关系、按当时可见前缀的 top-k 与故事线排序、期望 cadence（director-review/text-only/defer/duplicate）、可能误报及理由。部分状态没有充分事实时允许 `abstain`，不能为了追求 Recall 强行猜测。

必须保留**所有**中途红灯，修复措施与未解决错误逐条报告。新样本上有危险假因果、来源穿越、未来剧透或不具备画面资格却越过权限的行为都记 `FAIL`；不因总体数值漂亮而忽略。
