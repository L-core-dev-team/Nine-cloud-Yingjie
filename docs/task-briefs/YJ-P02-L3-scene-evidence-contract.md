- `AGENTS.md`、`docs/handoff.md`、`docs/decisions.md`、最新报告与本任务书。

首先明确每个字段可从哪里得到、何时**不能**得到：

| 目标 | 必须有的证据与判断 | 缺失时 |
| --- | --- | --- |
| sceneId、地点名和父区域 | 正文明确人物抵达/身在某地点，且同名地点可唯一辨认；稳定 ID 由受信场景索引决定而不是模型自报 | 不创建新的已访问地点 |
| 当前所在与观察位置 | 明确当前玩家身处/从哪观察及哪个方向或视角，不能用历史镜头、世界书候选或图片随机细节补齐 | viewpoint / perspective 不确定，不能 ready |
| people 完整名单 | 明确的在场成员或明确证据支持完整数量（例如“堂内只有……”）；“A/B/C在场”仅可登记至少这三人 | observedPeople 为局部事实，不准覆盖全量 people |
| features | 当前可见的结构、陈设；固定结构要有可靠同地点来源与逐句证据 | 不补写建筑、秘密机关或隐藏人物 |
| timeOfDay、lighting | 当前文字/权威已保存状态支持；“阳光明亮”不自动等于已证实具体日间时刻 | 未知字段保留未知 |
| 作用域与原文证据 | 每项标明已保存 `source`、UTF-16 offset/length、rule、当前事实类别与权限；引用应能复核真正子串 | 未通过完整校验时不构造可送图的 ready |

上述是首版**严格的可送图标准**，不是要求模型每次强行补齐所有信息；故事本来没有说的，应继续显示文字、暂不出图。世界书中未触发/未揭示的设定不能冒充当前目击事实。

## 2. 工作包 A：零网络的场景证据合同（首要）

优先在映界仓库内设计简单、版本化的 `scene-evidence/1`（目录/文件按实际工程合理安排），给未来的文字响应和映界消费之间提供明确的**受信、可审计、可放弃判断**的数据结构。

建议两个独立层次：

**A. 故事正文（authoritative）**：仍然由九霄普通 `CardImportService.act` 保存的 completed-history 正文，任何事实来源于这个已完成历史或当前会话已确认的之前状态；不能由前端 action、模型隐藏 JSON、YJ-02 固定图片或世界书未经揭示的条目新增事实。

**B. 可见证据审计（derived）**：`source`、本次 `revision`、`narrativeSha256`、场景候选与每个可见字段的原文 span、证据类型（明确当前、记忆、计划、转述、含糊、否定、未知）、字段精确性（完整/局部/未知），以及 `ready/not-ready` 与原因。它是**可验证的提取结果，不是第二份剧情权威**。

要求审计在发现非当前语境、混合引语、跨地点含糊、重复地点名、世界书秘密或人物完整性不明时拒绝“自动建图”。单有准确文本子串/sha 并不等于语义事实正确；每项匹配应保留受限语义规则/人工标注来源，合成用例须有独立于运行时的明确期望标签。未知字段不能偷偷补默认值。

**不要在主线未批准更改 /2 的情况下直接切换默认 extractor。** /3 已经是 replayOnly，不要把局部 observedPeople 偷偷塞进公共 `VisualSchema.people`。如需新 `/4` 或旁路 `scene-evidence/1`，在隔离新库运行并记录兼容性/版本迁移/回退方案。

## 3. 工作包 B：未来文字生成时的“自然叙事 + 当前场景调查”模板

现有 L1 只有一次 92 输入、39 输出 tokens 的真实调用。要得到稳定画面，应该改进**未来新请求的上下文与信息契约**，而不是修改已经保存的 L1 正文，或让画面模型猜数据。

交付不触网的**受信文字提示模板/测试 fixture**：

- 对于首次进入场景，提示模型用正常小说叙述完整交代当前地点与所属区域、玩家视角/观察位置、明确可见结构、当前时段和光照、当前人物；“全部在场成员”只在剧情确实建立完整调查时才表述为完整。
- 没有得到的信息明确保留为未确定。不要让模型必须生成“不存在依据的三人、柜台、东村”等固定项目示例；在未来自由剧情里只能使用实际允许创造且在**同一篇已保存剧情明确表现**的内容。
- 不要强制在玩家可见正文里插入暴露内部字段名的 JSON、模型 chain-of-thought、未揭示设定或供图像模型看的秘密提示。
- 允许剧情是简短交谈，没有视觉变化则复用或跳过；不是每一轮都要完整“场景调查”。离开、复访和场景变化的现有 /2、YJ-09/10 规则继续生效。
- 若未来采用“单次模型响应同时包含叙事和结构化辅助字段”，辅助字段也必须被已保存叙事的明确证据支持，且在九霄原会话持久化中有一致性/校验路径；**不能只因模型 JSON 声称“完整三人”便承认该事实**。在本阶段仅离线比较设计，不改上游权威历史写入协议。

用合成酒馆（例如东村/西村同名酒馆）之外另准备至少一组新场景与负样本，以检验不是针对那次真实正文做特殊硬编码。模型提示模板必须是候选，**没有下一次真实 Luna 调用时只能标 OFFLINE_PROMPT_VERIFIED，不能宣称生成质量提升**。

## 4. 工作包 C：实际的隔离 PG、HTTP 和 Chrome 测试

首先保护 YJ-13/P01/L1/L2 基线：

1. 使用合成正文经原九霄普通角色卡**真实浏览器页面保存**，通过鉴权 Cookie 读取 `completed-history`，再由映界投影。同样本地 mock 文本，不调用 OpenAI。
2. **合格首回合**：完整地点、可见名单、已知视点/视角、结构和时段/光照都有文本证据，触发新隔离投影 `ready` 并能稳定复播，sceneId 唯一；本项强制关闭图片发送，所以 `image.task/attempt/sends=0`。
3. **不合格首回合**：只提到三位人物在场、当前日光、陈设，没有地点和完整视角，如 L2 的真实类别；必须 `not-ready`，有审计证据但不产生可展示的画面。
4. **负向**：玩家行动声称地点但保存正文没有；计划明天前往、梦、转述、未揭示隐藏房间、双重地点、同名不同村、非排他名单、人物下落不明、未知时段、模型输出多余 JSON 提示、旧图错误复用；不得自动补事实。
5. **连续性**：初次完整调查→一般谈话不重建视觉版本→明确人物到来→离开重访及保守跳过；跨账号/跨会话/同名别名不串。
6. 首回合完备度的“可显示”判定必须在现有 `scene-state/project.mjs` 审核下成立，不添加绕过其 `fields` 或用户当前知识过滤的快捷通道。
7. 必须可回退到原 /2、/3，所有旧版本历史审计依旧可只读复核；旧 L1 原剧情回放仍为 `not-ready`，不要将真实旧事件重写成 ready。
