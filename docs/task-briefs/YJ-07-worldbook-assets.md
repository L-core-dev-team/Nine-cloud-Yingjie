## 2. 边界与现有工程事实

- 九霄目前有角色卡导入和世界书。上游 `CardImportService` 将角色卡内的 `character_book`、已关联世界书及会话创建时固定的全局世界书用于文字模型上下文。**世界书的原文/触发条目不是“已发生剧情”**；不能把“某角色会出场”“某地点存在藏宝图”等文本直接升格为玩家眼前的事实。
- 已核对的 `selectWorldbookEntries` 用于文字模型条目选择，返回 content、position、order，不保证提供映界可持久引用的世界书版本、entry ID 或视觉资产身份。不得把其返回顺序当成不变的图片素材主键。
- 实际宿主使用已认证的 owner、session 和既有来源关系。普通角色卡 `history` 与 YJ-04 投影用于确立发生过的事实，**世界书用于辅助地点说明/候选资料，而不是覆盖剧情。**
- YJ-05 资产记录按用户/会话/地点/视觉快照核对；一般预设资源不等同于可跨会话访问的普通生图 Asset。若要从共享或用户个人素材目录选用资源，应先核对资源来源、合法用途和访问范围，再通过受信映射或按会话物化；不能绕开既有 scope 规则伪造用户资产。
- 与万卡阁严格隔离。不能自动扫描万卡阁、Discord、其他私人仓库或第三方账户来“补充素材”；不能默认导入/转载他人的图片有再分发许可。
- 本轮没有获准的独立后端图片 API 与认证，不做真实图片服务调用、不编造费用或供应商能力。可用固定合成数据和已有获准样例进行离线与本地集成验证。

## 3. 核心交付 A：受信世界书来源适配

实现最小只读世界资料适配器，优先基于既有独立角色卡会话：

1. 从受信九霄宿主取得 owner、sessionId 和相关版本引用；先验证当前会话及访问权，不接受浏览器传入的 ownerId、任意 importId/路径充当授权。
2. 确定并记录该会话可用的世界书来源：角色卡内嵌的 `character_book`、与当前卡关联的世界书、创建会话时固定的全局世界书。现有实现有群聊特殊分支；本任务首先限定普通角色卡。与既有文字会话的来源集合对齐，不能直接读取用户所有 imports 然后声称都适用。
3. 为可用条目记录可追溯的来源：类型、受信 import/card 标识或合成夹具 ID、内容/版本摘要、适用会话或明确许可范围、校验依据。若当前 API 不暴露足够元数据，可选用服务端内部只读适配器或最小受信接口，并记录补丁与鉴权；不伪造永久条目 ID。
4. 处理解析失败、不支持的规则、空世界书和资源被删除/失效等情况。不能悄悄放宽上游世界书限制，也不能把世界书里的工具指令当成程序指令执行。
5. 在访问被撤销、会话改变或角色卡/世界书版本变动时，重新校验适用范围；会话创建时固定的世界书不应因后来全局启用列表变化而被错误替换。

## 4. 核心交付 B：地点标签与可见事实对照

建立小型、可解释的“地点资料候选”匹配器：

- 输入：YJ-04 ready 的 Scene、Visual、稳定 `sceneId`、当前已保存的剧情来源，和已确认有权使用的世界书条目；not-ready 不进行强行匹配。
- 输出：有明确来源和理由的候选地点标签、固定结构描述、已获准资源候选，或带原因的 `no-match` / `not-ready` / `ambiguous`。
- 优先使用已确认 `sceneId` + 受信地点关系；名称、别名、同村/异村范围等只作有依据的次级条件。不能仅靠字符串包含、同名或 LLM 猜测，把不同村庄的酒馆合并。
- 世界书里提到的未来、传说、回忆、秘密、未证实人物不能被写进当前 `Visual.people`、地点现时状态或玩家可知事实。必要时仅作为低信任候选并留待审阅。
- 保留固定地点特征及视觉版本；若场景确实从三人变五人，预设三人图即使地点名称吻合，也**不再可直接展示为五人场景**。旧图是否可作为编辑参考由 0.1.1 参考资格规则处理，不能自行放宽。
- 无对应世界书时不得阻断文字；无匹配素材时返回清楚的无匹配状态，后续若有图片服务才能交给动态生成/编辑策略。

## 5. 核心交付 C：预设图片目录与选用

创建最小受控素材索引，而非大量生产新图：

| 索引信息 | 目的 |
| --- | --- |
| 资源 ID、类型、实际来源与使用许可/授权范围 | 能确定素材来自哪里、允许用于哪个用户/会话/项目 |
| 原件路径或安全存储键、SHA-256、格式、尺寸 | 能验证真实文件；不得信任任意客户端文件路径 |
| stable sceneId 或可核实的地点标签/别名 | 不因地点改名而误换资源，同名异地不误匹配 |
| 视觉版本或适用条件（人、结构、时间、视角、已知事实） | 防止旧预设图违反当前剧情 |
| 审阅状态与依据 | 待审、矛盾或无法判断不强行显示 |
| 版本/失效标识 | 更换素材可追踪，不覆盖已引用的历史资产 |

允许用 YJ-02 的原 I0/I1/I2 **作为明确标注的测试预设图**，但它们只是合成酒馆示例，不自动变成九霄修仙世界的通用正式素材。已有九霄 WEB 山门等界面装饰图片也不自动等于场景插画或具备可再分发许可。

匹配策略应先核实权限与字节；只有同时满足当前 Scene/Visual 的归属、事实、审阅及适用条件才返回可供 05/06 使用的预设候选。素材缺失、摘要损坏、权限变化、版本冲突、同名异地、错误视角时必须返回拒绝或无匹配，不要用“不知道但是看起来差不多”填充结果。

避免改写 YJ-05 的任务去重语义和资产权限边界。需要新增 preset 资产类别或可复用映射时提出最小扩展，明确跨会话资源独立身份、归属和授权；由同一集成负责人控制公共契约和数据库迁移。

## 6. 核心交付 D：接入前端与后续出图决策

- 在现有 05/06 本地演示宿主中加入“已审核预设匹配 / 无匹配 / 不适用”读取路径。可用独立服务适配器、由已鉴权宿主返回最小显示记录；不让 React 浏览器直接打开项目私有文件、访问 PG 或任意本地路径。
- 优先预设匹配时，合格资产可被显示或复用；无匹配时不能自动拿三人旧图假装五人场景。动态生成或参考编辑只作为后续可验证的决策候选，没有获准 Provider 则保持无图/未启用。
- 生图关闭时应保持文字流程正常，不主动创建远端图片任务。预设图片的显示策略要明确：现有开关代表禁用新生图，还是隐藏全部图片，目前未正式冻结；本任务记录演示行为，不能擅自升级成最终产品决定。
- 如果触及上游原角色卡页面，使用隔离工作副本与可回退挂载方式，不修改九霄 `main`，不复制全部九霄代码到映界。

## 7. 必须验证的代表性场景

1. **现有九步酒馆不回退：** 在同一模块组合下，三人图、普通交谈复用、五人到场、复访、傍晚灯光、关图、失败、刷新、切会话的既有行为仍在。此用例可以先做定向回归，勿重复付费生图。
2. **预设匹配：** 同一酒馆在 V1 可选择 I0；V2 的五人图匹配 I1；V3 的傍晚五人图匹配 I2。图像来源必须明确为已存在的测试原件。对应规则不适用时清楚拒绝，而非沿用错误旧图。
3. **无匹配：** 无世界书/无预设图、地点不明、视觉事实不足、图片损坏、未审阅、使用权不足，都返回可区分状态；文字仍能继续。
4. **地点与版本：** 别名改名不换 sceneId，东/西村同名酒馆不合并；普通交谈不产生新的视觉版本，已确认增人/点灯产生适当新版本。
5. **来源与权限：** 同用户的其他会话、他人的导入、无关世界书、撤权/删除后缓存，不能因为名称相同进入当前资源候选；旧请求迟到不覆盖新会话。
6. **世界书规则：** 只引用本会话实际关联、已获准的世界书；未知特性按现有受限解析处理，不擅自替代文字模型世界书选择器；会话快照与后续全局更改的关系被验证。
7. **现在 vs 回忆/传闻：** 世界书写到 NPC、远方山峰、秘密和未来事件时，不将这些内容直接加入当前在场人物或在当前图片显示玩家尚不知道的信息。
8. **真字节与重启：** 在本地存储中回读获准测试图片，检查 SHA-256；重启后索引、地点关联及当前显示资格仍然成立；损坏或删除后资格被撤销。

至少有真实本地 Node/PostgreSQL 和受鉴权 HTTP 的针对性检查，合成素材与真实用户授权资料分别标注；不要求真实模型调用。源世界书若当前环境没有获准可读样本，就用明确合成的、与既有结构兼容的 fixture 测试规则；不能声称已验证私人实际世界书。
