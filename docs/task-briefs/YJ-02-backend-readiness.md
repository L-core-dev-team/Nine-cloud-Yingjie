## 二、必须完成的四项工作

### 1. 核查已有后端接入条件

从现有源码、配置模板和已获准的运行上下文确认：

- 是否已有图片生成或参考编辑入口，分别位于哪里。
- 需要哪些配置名称；现有环境是否具备，哪些仍缺失。
- 文生图、参考图、结果下载、请求标识、查询和取消分别有什么实际证据。

只记录配置名称、存在/缺失/未知及脱敏依据；不读取或输出真实密钥，不遍搜私人配置，不以登录某个平台推定已获准后端调用。只有已存在的候选服务才核查其官方说明，不为本任务做多供应商选型。

若没有实际后端入口，明确写“未发现”，继续下面的离线准备。不能把 Codex 会话工具当作已接通的九霄服务。

### 2. 实现最小 dry-run 请求准备入口

在独立实验目录中完成，例如 `experiments/yj02-backend-readiness/`。复用现有 `@yingjie/contracts@0.1.0`，不复制出第二套公共 schema。

这个入口只需要：

- 加载已存在的合成酒馆样例和计划，区分生成、编辑、复用与跳过。
- 读取所选参考资产、核对内容摘要，调用已有契约规则检查参考关系。
- 为一次拟执行请求准备脱敏的逻辑输入与尝试记录。
- 复用/跳过不建立图片发送；编辑请求明确保留参考资产、摘要及变化要求。
- 默认 dry-run，不发送外部请求，不调用图片工具；缺少配置时输出可理解的缺口并正常收口。

没有已确认供应商协议时，输出应称为“逻辑请求准备结果”。不得猜测 URL、请求字段或 SDK 后，宣称已经得到可直接发送的供应商请求。

原 I0/I1/I2 可用于读取、引用和核验。原始图片、原始调用记录及审阅结论保持原样；准备结果写入新的实验输出位置。

### 3. 做少量本地 mock 传输验证

使用注入的本地模拟函数即可，不要求搭服务器。目的只验证“准备结果交给传输边界后怎样记账”，不实现正式图片服务。

覆盖以下有实际价值的情况，避免重做 YJ-03 已有的整套字段测试：

| 情况 | 要证明的行为 |
| --- | --- |
| 正常模拟返回 | 可以关联原尝试、目标与结果；明确标记 mock，不伪造真实生图 |
| 没有远端请求标识或用量 | 保留未知，不拿本地 ID 冒充远端 ID，不把费用填成 0 |
| 明确失败 | 记录可区分的失败及原因，准备入口能够正常退出并留下记录 |
| 发出后结果未知 | 保留原尝试，不自动再次调用模拟发送函数，也不推断远端已取消 |
| 缺配置或 dry-run | 外部图片调用为 0；拟请求与实际发送分别统计 |

模拟返回如果引用了原实验 PNG，要注明它来自既有工具实验，仅用于离线传输回执，不把它计为新生成图片。能力记录的 origin 与证据方法要与本次 mock 相符。

日志只保留需要的脱敏信息。用合成敏感值检查不会把认证字段、带凭据的下载地址或完整原始响应写入输出；不使用真实凭据测试脱敏。

### 4. 形成映射、缺口和复跑说明

交付一份简明报告，说明：

- 准备入口的输入、输出怎样映射到现有 Decision、Attempt、Capability、Asset 等契约。
- 当前确有证据的能力、明确不支持的能力、仍未知的能力。
- 下一次真实后端实验具体缺哪些条件。
- 条件具备后从哪条实际命令或哪个入口继续，哪些部分仍需按真实供应商协议补充。
- 本次执行过的检查、结果和未执行项。

公共契约若表达不了必要信息，将最小差异写入报告，交给总集成协调；不要在 02 分支直接改公共 schema、版本、根依赖或锁文件。

## 三、并行与范围

这轮允许独立实验脚本、必要本地样例、离线检查和文档。优先使用已有包与运行时，不增加不必要的依赖。

以下属于后续 YJ-05 等任务，本补充不要求提前建设：

- 完整 Provider 框架、生产 HTTP/SDK 适配器、自动调度或后台轮询。
- 数据库迁移、持久队列、跨进程恢复、自动重试和正式图片存储服务。
- 前端界面、真实剧情提取、完整会话到图片联调。
- 第二套账号、存档、世界书或公共数据格式。

本实验中的模拟响应只是传输测试输入，不是永久供应商协议。无法确认结果且无已验证核对方式时保留 unknown；不把查询、回调、取消或幂等能力预先写成已支持。

03 的现有格式在本轮作为消费基线。其他分项目继续推进时，各自在自己的分支工作；02 把实际观察和差异反馈给公共契约维护者，不覆盖对方成果。
