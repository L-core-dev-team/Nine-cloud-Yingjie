## 一、任务目标

接手《九霄 · 映界》YJ-06。先核查实际仓库、分支、工作区和九霄既有 React/Vite 页面、会话导航与角色卡游玩入口，然后在隔离任务分支实现最小映界前端：**文字照常游玩；旁边或可切换区域展示当前可用的场景图、等待/失败状态和生图开关。** 手机窄屏和桌面宽屏均可操作。没有后端图片 API 时可用明示的合成画面样例做 UI 检查，但不得宣称自动生图已接通。

这是九霄现有页面内的映界模式，不另建一套帐号、登录、存档和完整文字游戏。映界仓库目前并不包含完整九霄前端源码；实现者应先确定采用的隔离上游副本、挂载点和打包验证方式。如果需要九霄修改，在独立上游工作副本/分支制作明确的可移植补丁，不写九霄 main，不覆盖其它 UI 开发者的工作。

必读：`AGENTS.md`、`docs/handoff.md`、[YJ-04 场景状态报告](../reports/YJ-04-scene-state-report.md)、[状态模块入口](../../packages/scene-state/README.md)、[共用契约](../contracts/visual-contracts-v0.1.md)、本任务书与 [YJ-02 样例报告](../reports/YJ-02-image-capability-report.md)。

## 二、首版 UI 必须包含的状态

| 输入或状态 | 必须呈现 |
| --- | --- |
| 场景 ready，已有匹配且可显示的图片 | 场景图、来源/场景基本标识、当前文字内容；同一张图可以随普通交谈继续复用 |
| 场景 not-ready、没有可见事实、地点不明 | 保留文字区，图片区显示清楚的“暂无线索/未准备好”状态，不伪造地点和图片 |
| 已准备请求或等待中 | 只显示准确的本地等待状态，不承诺固定生成时间；玩家仍能继续适用的文字操作 |
| 请求失败、拒绝或返回结果未知 | 区分失败、被拒绝与未知，不把未知当成确定失败后自动再次付费请求 |
| 图片结果返回但未接受审阅/不适用 | 不抢占当前画面；允许保留诊断信息但默认不显示为当前场景 |
| 玩家关闭生图 | 不提交新的图片请求，文字照常继续；本地“停止等待”与服务端取消应有清晰区别 |
| 玩家切换会话、离开地点、刷新 | 旧会话/旧视觉版本的迟到结果不能顶替当前视图；重新读取当前场景状态 |
| 狭窄屏幕与键盘操作 | 图片与文字都可读、开关可触达；不应产生遮挡或无法滚动的布局 |

图片可无图、可复用、可失败，但必须避免“为了占满位置而展示错误图片”。界面上的“当前画面”不得自动把图片偶然多出的物件写入权威剧情。

## 三、数据来源与实现方式

- 场景数据直接消费 YJ-04 的 ready/not-ready 语义和已有 `SceneSchema`、`VisualSchema`；图片任务侧以 `Decision/Attempt/Asset` 的既有语义作为模拟与后续接口输入，不复制新的公共数据格式。
- YJ-04 的 `syncCardHistory` 在受信 Node 宿主中运行，**不能把 PostgreSQL 连接池、认证 Cookie、私有数据库记录直接暴露到浏览器**。本轮可以使用明示的开发模拟适配器；需要真实 HTTP 显示接口时先与总集成确定准确权限边界和接口契约，不能临时加入不受控公开路由。
- 首次开发可以使用三张已获准的酒馆原图作为清楚标记的“固定样例模式”。必须保留其原有来源与只读性质，不能标成实时 AI 出图，也不能新增模型调用来做 UI。
- 映界生图开关的永久保存范围尚未冻结：先实现可检查的局部状态，记录重开/切换时的实际行为，不擅自将测试选择升级成正式跨设备产品设置。
- YJ-05 通用图片任务可以和本轮并行；其真实结果 API 尚未就绪时，06 消费统一样例契约，不等待实际供应商。

## 四、具体实施顺序

1. 核对上游页面、路由、组件与实际构建命令，确定最小映界入口和负责展示的组件；记录具体文件及其与现有文字游玩会话的关系。
2. 建立有边界的场景视图数据适配器，输入为授权后得到的当前会话状态和可展示资产资格；ready/not-ready、当前场景与图片审阅/结果状态分离。
3. 实现文字区保持可用、图片区和开关；同地点无变化时保持旧图，不因新文字回合机械清空画面；当前状态不匹配时保守留空。
4. 用合成酒馆 3 → 5 → 5 图片样例、普通对话复用、无变化复访、傍晚更新测试画面流转；样例为实验模式，真实会话自动出图 NOT_RUN。
5. 验证 UI 的等待、失败、拒绝、未知、关闭、切换、迟到与刷新；对待审或错误归属结果做明确拦截。
6. 在桌面及移动尺寸浏览器中进行布局、输入、图片比例、滚动、聚焦和键盘操作检查。模拟 viewport 不等于手机真机，需单列。
7. 提交运行/构建报告、可复现 demo 或隔离上游补丁、截图或测试证据，并更新任务和交接。不可只提交设计图或静态组件而声称整个界面链路通过。

## 五、必须验证的边界用例

- 三人初图正常显示；普通对话仍显示 I0；五人到场后使用 I1；无变化复访继续显示 I1；傍晚视觉版本已变时显示匹配 I2，旧图不能抢占新状态。
- 同一会话的两个回合可共用视觉版本，不能仅因 source.key 变化判图片过期。
- 切换到另一账户、会话或地点，原图不再被当作当前图片；仅凭浏览器带入的 ownerId 不获得访问授权。
- 关闭生图期间不自动发请求；关闭 UI/停止等待不能显示为供应商已确认取消。
- 结果未知、供应商拒绝、加载资源失败、缺少图片、未审阅或校验失败时文字可以继续。
- 宽/窄屏布局、文字区滚动、图片不意外拉伸、交互控件键盘可操作；浏览器响应式测试和真机测试分别记录。
- 页面刷新后从持久来源或明确样例恢复显示，而非依赖上一轮 JS 内存；涉及真实数据时要有宿主权限验证。
- 对 UI 中采用的素材标明实际来源，绝不将模拟样例或 Codex 工具图片说成九霄本次自动生成。

## 六、交付、范围与收口

交付至少包含：可运行的映界前端入口/最小组件、数据适配与模拟样例、与原文字玩法并存的证明、响应式和状态转换测试、准确的上游挂载/回退说明、`docs/reports/YJ-06-ui-report.md`、脱敏证据、任务状态和交接。

并行职责：YJ-06 负责展示与操作，不修改 YJ-05 的任务状态语义、不直接写 YJ-04 投影库；05 负责持久任务、结果、权限和恢复。公共 schema、九霄统一路由、根依赖或迁移须总集成协调。两线各自使用独立分支，最终在 YJ-08 做一次真正的文字→场景→任务→图片→展示联调。
